# 2026-05-19 AI 요약 워커 수정 이력

## 증상
- 매각물건명세서 텍스트는 수집됐지만 UI에는 원문이 길게 보여 사람이 읽기 어려웠다.
- `court-auction-insights worker-once` 실행 시 명세서가 없는/대기 중인 물건에서 멈추거나, 최신 다운로드 명세서가 있는데도 요약 대상 선정이 불안정했다.
- `gemma4:26b` 호출이 120초 제한에 걸려 실패했다.

## 원인
- AI 요청 프롬프트에 `asdict(auction)` 전체를 넣어 매각물건명세서 반복 양식, 개인정보 경고, 긴 원문 전체를 매번 보냈다.
- 26B 로컬 모델은 첫 호출 메모리 로딩 시간이 길 수 있는데, 타임아웃이 120초로 짧았다.
- 모델 호출 실패 시 실패 이력을 남기지 않고 예외가 그대로 터져 워커가 중단됐다.

## 조치
- 매각물건명세서에서 반복 양식/개인정보 경고/구분선을 제거하고, 지분매각·특별매각조건·임차·점유·대항력·배당요구·전유면적·대지권·회차별 최저가 등 판단 핵심 키워드 중심으로 축약해 보낸다.
- Ollama 타임아웃을 `INSIGHTS_OLLAMA_TIMEOUT_SECONDS`로 설정 가능하게 하고 기본값을 600초로 늘렸다.
- 명세서 다운로드 완료 건만 AI 요약 대상으로 삼고, 대기/미업로드 건은 워커가 건너뛰도록 했다.
- 모델 호출 실패는 `auction_enrichments.status='failed'`와 `error_message`로 저장해 원인 추적이 가능하게 했다.
- 반복 실행용 `court-auction-insights worker-loop` 명령을 추가했다.
- 프롬프트 정제 방식이 바뀌었으므로 기본 `INSIGHTS_PROMPT_VERSION`을 `v2`로 올려 기존 실패/성공 이력과 분리했다.

## 검증 기준
- 컴팩트 프롬프트 길이가 과도하게 커지지 않아야 한다.
- 다운로드 완료 명세서가 있으면 대기 상태 레코드 때문에 막히지 않아야 한다.
- 모델 호출 실패 시 워커가 죽지 않고 실패 이력을 남겨야 한다.
