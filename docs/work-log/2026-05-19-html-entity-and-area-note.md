# 2026-05-19 HTML entity 디코딩 및 면적 참고 표시

## 작업 내용
- 크롤러 수집 로직은 건드리지 않고 인사이트 표시 계층만 수정했다.
- `appraisal_summary`의 HTML entity를 디코딩해 `&quot;`가 화면/API에 그대로 보이지 않도록 했다.
- 현재 저장된 감정평가 요약 안에서 면적 관련 문장을 `area_note`로 추출해 목록/상세에 표시하도록 했다.

## 오류 증상
- 감정평가 요약에 `&quot;은성중학교&quot;`처럼 HTML entity가 그대로 표시됐다.
- 상세 페이지 원문에는 면적 단서가 있을 수 있는데 현재 화면에는 면적 관련 단서가 전혀 드러나지 않았다.

## 원인
- 인사이트 API가 crawler DB의 텍스트를 HTML entity 디코딩 없이 그대로 내려줬다.
- 전용/공급면적은 현재 crawler DB 별도 컬럼으로 저장되지 않는다.

## 조치
- `CrawlerSource`에서 `html.unescape()` 적용.
- `AuctionSourceRecord.area_note` 추가.
- 감정평가 요약에서 `전유면적`, `전용면적`, `공급면적`, `건물면적`, `대지권`, `대지면적`, `면적은`, `㎡` 키워드가 있는 첫 문장을 `area_note`로 추출.
- API 직렬화에 `area_note` 추가.
- 목록 카드와 상세 화면에 면적 참고 문장 표시.

- RED:

  - `area_note` 필드 부재 테스트 확인.
- GREEN:
  - `pytest -q` → `27 passed in 0.54s`
  - `npm run build` → 성공.

## 결과/남은 확인
- 현재 저장된 데이터 안에서 확인 가능한 면적 관련 단서는 화면에 표시된다.
- 진짜 전용면적/공급면적/대지권면적을 정규 컬럼으로 쓰려면 crawler 상세 파싱에 별도 안전 작업이 필요하다.
