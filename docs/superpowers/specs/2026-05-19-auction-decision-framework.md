# 경매 물건 판단 프레임 / 데이터 사전 / 화면 구성

작성일: 2026-05-19  
대상 프로젝트: court-auction-insights / court-auction-crawler

## 목적

이 서비스는 경매 물건 목록을 예쁘게 보여주는 서비스가 아니다. 사용자가 얻고 싶은 것은 “이 물건을 더 조사할 가치가 있는지”에 대한 1차 판단이다.

따라서 모든 데이터와 화면은 아래 질문에 답해야 한다.

1. 가격 메리트가 있는가?
2. 물건의 실체를 대략 파악할 수 있는가?
3. 경매 진행 이력이 이상하지 않은가?
4. 매각물건명세서상 위험 신호가 있는가?
5. 사람이 추가로 봐야 할 물건인가?
6. 오늘 우선 확인할 후보는 무엇인가?

## 핵심 원칙

- 수집된 원문을 그대로 나열하지 않는다. 판단 가능한 형태로 구조화한다.
- 불확실한 값은 단정하지 않는다. `확인 필요`, `원문 근거 부족`, `명세서 미확보`로 표시한다.
- AI 분석은 원문을 대체하지 않는다. AI는 1차 선별과 체크리스트 생성 역할이다.
- 목록 화면은 “후보 선별”, 상세 화면은 “검토 근거 확인”에 집중한다.
- crawler 안정성이 흔들리는 변경은 별도 계획 없이 하지 않는다.

## 사용자가 실제로 하려는 판단

### 1. 가격 판단

질문:

- 감정가 대비 얼마나 싸졌는가?
- 유찰 횟수가 가격 하락을 설명하는가?
- 최저가가 내 관심 예산 안에 들어오는가?
- 같은 지역/유형 대비 싼 편인가?
- 면적 대비 가격이 합리적인가?

필요 데이터:

| 필드 | 출처 | 상태 | 비고 |
|---|---|---|---|
| 감정가 | 상세 페이지 | 수집 중 | 현재 있음 |
| 최저매각가 | 상세 페이지 | 수집 중 | 현재 있음 |
| 할인율 | 파생 | 구현됨 | `(1 - 최저가 / 감정가)` |
| 감정가 대비 차액 | 파생 | 구현됨 | `감정가 - 최저가` |
| 유찰 횟수 | 상세 페이지 | 수집 중 | 현재 있음, 정확도 보강 필요 |
| 회차별 가격 | 상세 기일 이력 | 미구현 | auction_events 필요 |
| 전용/공급면적 | 상세/명세서/감정서 | 미구현 | 현재는 area_note만 임시 표시 |
| ㎡당 가격 | 파생 | 미구현 | 면적 정규화 후 가능 |

### 2. 물건 실체 판단

질문:

- 실제로 어느 아파트/건물인가?
- 몇 층인가?
- 전용면적/공급면적은 얼마인가?
- 노후도는 어느 정도인가?
- 사진상 상태는 어떤가?
- 주변환경/교통은 어떤가?

필요 데이터:

| 필드 | 출처 | 상태 | 비고 |
|---|---|---|---|
| 주소 | 상세 페이지 | 수집 중 | 현재 있음 |
| 구/동 | 주소 파생 | 일부 구현 | 구는 있음, 동 파싱 필요 |
| 건물명 | 주소/상세 | 미구현 | 주소에서 우선 추출 가능 |
| 층/호 | 주소/상세 | 미구현 | 정규식 추출 가능 |
| 전체 층 | 감정요약 | 미구현 | “15층 건물 내 4층” 패턴 |
| 사용승인일 | 감정요약 | 미구현 | “사용승인일” 패턴 |
| 면적 | 상세/명세서/감정서 | 미구현 | 중요한 다음 후보 |
| 사진 | 상세 페이지 | 수집 중 | 현재 있음 |
| 위치/교통/주위환경 | 감정요약 | 수집 중 | 현재 원문 있음, 요약 필요 |

### 3. 경매 진행 이력 판단

질문:

- 몇 번 유찰됐는가?
- 매각됐다가 대금미납으로 다시 나온 물건인가?
- 변경/취하/불허가 이력이 있는가?
- 가격이 어떤 흐름으로 내려왔는가?

필요 데이터:

| 필드 | 출처 | 상태 | 비고 |
|---|---|---|---|
| 기일 일자 | 상세 페이지 기일 표 | 미구현 | raw row 저장 필요 |
| 기일 종류 | 상세 페이지 기일 표 | 미구현 | 매각기일 등 |
| 기일 가격 | 상세 페이지 기일 표 | 미구현 | 회차별 최저가 |
| 기일 결과 | 상세 페이지 기일 표 | 미구현 | 유찰/매각/변경/취하/대금미납 등 |
| 재진행 의심 | 파생 | 미구현 | 매각 후 미납/불허가 등 감지 |

제안 테이블:

```text
auction_events
- id
- auction_id
- event_date
- event_type
- event_price
- event_result
- raw_text
- captured_at
```

1차 구현은 결과를 과해석하지 말고 raw row를 보존한다. 의미 분류는 2차로 붙인다.

### 4. 매각물건명세서 리스크 판단

질문:

- 점유자가 누구인가?
- 임차인이 있는가?
- 대항력/우선변제/배당요구 관련 위험이 있는가?
- 인수될 권리나 특수조건이 있는가?
- 관리비/체납/유치권/법정지상권 같은 위험 문구가 있는가?

필요 데이터:

| 필드 | 출처 | 상태 | 비고 |
|---|---|---|---|
| 명세서 업로드 여부 | 상세 문서 버튼 | 수집 중 | 있음 |
| 명세서 PDF | 문서 다운로드 | 일부 성공 | 안정화 필요 |
| 명세서 텍스트 | PDF 추출 | 일부 성공 | 품질 확인 필요 |
| 점유/임차 요약 | AI/룰 기반 | 미구현 | 핵심 가치 |
| 위험 문구 | 룰 기반 + AI | 미구현 | 키워드 하이라이트 |
| 사람 검토 필요 여부 | AI 판단 | 미구현 | 모바일 카드 핵심 |

명세서가 없는 물건은 버리지 않는다. 대신 UI에 다음처럼 표시한다.

```text
명세서 미확보: 현재 가격/사진/감정요약만으로 1차 확인 가능. 권리·점유 리스크 판단 불가.
```

### 5. AI 분석 판단

질문:

- 이 물건을 왜 봐야 하는가?
- 왜 조심해야 하는가?
- 사람이 무엇을 추가 확인해야 하는가?
- 지금 우선순위가 높은가?

AI 입력 후보:

- 주소/유형/가격/유찰/기일
- 감정평가 요약
- 매각물건명세서 markdown
- 경매 기일 이력
- 사진 자체는 1차에서는 입력하지 않음. 사진 수/존재 여부만 메타로 사용.

AI 출력 구조:

```json
{
  "summary_title": "한 줄 요약",
  "price_comment": "가격 메리트 설명",
  "property_comment": "물건 실체 설명",
  "risk_label": "low | review_recommended | high | unknown",
  "risk_comment": "리스크 판단 근거",
  "watch_points": ["사람이 볼 체크포인트"],
  "missing_data": ["명세서 없음", "면적 없음"],
  "priority_score": 0-100
}
```

## 화면 구성

### 목록 화면: 후보 선별

목록 카드는 아래 정보를 우선순위대로 보여준다.

1. 관심/주의/보류 배지
2. 주소 + 건물명/층/면적 가능 시
3. 최저가 / 감정가 / 할인율
4. 유찰 횟수 / 다음 매각기일
5. 명세서 상태
6. AI 리스크 한 줄
7. 사진 대표 1장

예시:

```text
[검토 추천] [명세서 있음] [AI 리스크: 확인 필요]
서울 은평구 응암동 응암푸르지오 104동 402호
최저 9.27억 / 감정 9.27억 / 할인 0%
전용면적 확인 필요 / 유찰 - / 기일 2026-05-19
코멘트: 명세서 확보 후 점유관계 확인 필요
```

### 목록 상단 요약

현재 구현된 summary strip을 확장한다.

- 전체 물건 수
- 명세서 확보/대기/미업로드
- AI 요약 완료/대기
- 사진 수
- 평균 할인율
- 유찰 2회 이상 물건 수
- 면적 확인 가능 물건 수

### 상세 화면: 검토 근거

섹션 순서:

1. 핵심 요약 카드
   - 가격, 할인율, 면적, 유찰, 기일, 리스크 등급
2. 사진
3. 가격/면적 정보
4. 경매 진행 이력
5. 명세서 분석
6. 감정평가 요약
7. AI 체크리스트
8. 원문

## 우선순위 로드맵

### Phase 1: 표시 품질 정리

목표: 이미 수집된 데이터로 판단하기 쉽게 만든다.

- HTML entity 디코딩
- 면적 참고문장 표시
- summary strip
- 할인율/차액 표시
- 명세서 markdown 표시

상태: 대부분 진행됨.

### Phase 2: 경매 판단 데이터 추출

목표: 상세 페이지 원문에서 구조화 가능한 값을 뽑는다.

- 건물명/층/호 파싱
- 사용승인일 파싱
- 면적 후보 파싱
- 기일 이력 raw row 저장
- 경매 이벤트 UI 표시

### Phase 3: 명세서 가치화

목표: 명세서가 있는 물건부터 유의미한 리스크 정보를 제공한다.

- 명세서 다운로드/추출 성공률 측정
- 추출 실패 원인 분류
- 명세서 markdown 품질 확인
- 룰 기반 위험 키워드 하이라이트

### Phase 4: AI 요약/리스크 분석

목표: 단건씩 로컬 Ollama/Gemma로 요약한다.

- 명세서 있는 건만 큐잉
- 한 건씩 처리
- 실패 재시도 제한
- 모바일 카드용 결과 저장
- 우선 검토 후보 화면 추가

### Phase 5: 추천/랭킹

목표: “오늘 볼 물건”을 뽑는다.

- 가격 메리트 점수
- 데이터 완성도 점수
- 리스크 점수
- 검토 추천/주의/보류 분류

## 데이터 품질 표시 규칙

- 명세서 없음: 리스크 판단 불가로 표시
- 면적 없음: ㎡당 가격 계산하지 않음
- AI 없음: AI 요약 전으로 표시
- 감정요약 없음: 원문 근거 부족 표시
- 기일 이력 없음: 유찰 횟수만 임시 표시
- 위험 신호가 있으나 불확실하면 “확인 필요”로 표시

## 다음 작업 기준

앞으로 기능 추가 전 항상 아래 질문에 답한다.

1. 이 데이터는 어떤 판단 질문에 답하는가?
2. 목록에서 보여야 하는가, 상세에서 보여야 하는가?
3. 원문 근거를 같이 보여줄 수 있는가?
4. 값이 없을 때 사용자에게 어떻게 설명할 것인가?
5. AI 분석 입력으로 쓸 수 있는가?

이 기준에 답하지 못하는 데이터는 우선순위를 낮춘다.
